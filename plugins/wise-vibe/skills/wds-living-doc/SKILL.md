# wds-living-doc — 요구사항 변경 전파

> 인자: `$ARGUMENTS` (`--type` 으로 유형을 지정하면 §1 분류를 건너뛴다)

이 스킬은 **개발 진행 중 언제든 추가되는 요구사항을 감지하고, 소스코드를 제외한 모든 문서를
일관성 있게 현행화**하는 로직을 담는다.

원칙: **문서는 코드보다 먼저 갱신된다.** 구현보다 앞서 PRD 와 README 가 확정 상태여야
다음 구현 이터레이션이 올바른 목표를 가진다.

## 0. 적용 조건 (trigger)

아래 중 하나 이상이면 이 스킬을 활성화한다:

- 사용자 입력에 다음 신호가 포함될 때:
  - **기능 추가**: "기능 추가", "기능도 만들어", "feature add", "also need", "also implement", "이것도"
  - **요구사항 변경**: "요구사항 변경", "수정해줘", "바꿔줘", "requirements change", "update PRD"
  - **비기능 변경**: "성능", "보안 강화", "캐시 추가", "rate limit", "auth 추가", "인증 추가"
  - **범위 변경**: "Out of scope 였는데", "이번에 포함하기로", "스코프 변경"
- `wds-living-doc` 직접 호출
- implement 절차 중 §PRD 분석 단계에서 PRD 에 없는 요구사항을 사용자가 직접 언급

## 1. 감지 및 분류 (Detect & Classify)

새 요구사항 인입 시 다음 항목을 먼저 결정한다.

### 1.1 요구사항 유형

| 유형 | 판단 기준 | 예시 |
|---|---|---|
| **F** (기능) | 사용자가 직접 사용하는 화면·API·동작 | 로그인, 상품 목록, 결제, CSV 내보내기 |
| **NF** (비기능) | 품질 속성, 제약, 운영 요구 | 응답 ≤ 200ms, JWT 인증, HTTPS 전용, Rate limit |
| **SCOPE** | In ↔ Out Scope 전환 | "Out of scope 였던 알림 기능 이번에 포함" |
| **DESIGN** | UI/UX 추가 사양 | 다크모드 지원, 반응형, 접근성 추가 |
| **COMPLIANCE** | 규제·보안·데이터 등급 변경 | 개인정보 동의 흐름, CSAP 요구, PII 마스킹 |

### 1.2 영향 문서 매트릭스

| 유형 | PRD.md | README.md | README.en.md | COMPLIANCE.md | AGENTS.md | SECURITY.md |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| F | ✅ §3 범위 + §4 흐름 | ✅ API/기능 | ✅ | — | 필요 시 | — |
| NF | ✅ §5 성공지표 또는 §7 기술메모 | ✅ §4 환경 | ✅ | — | 필요 시 | — |
| SCOPE | ✅ §3 In/Out | ✅ | ✅ | — | — | — |
| DESIGN | ✅ §4 UX + 디자인방향 | ✅ | ✅ | — | 필요 시 | — |
| COMPLIANCE | ✅ §6 리스크 + §7 NFR | ✅ §8 | ✅ | ✅ | — | ✅ |

## 2. 작업 순서 (always)

1. **현황 파악** — 다음 파일 존재 여부 확인 (Glob):
   - `PRD.md` / `prd.md` / `docs/PRD.md`
   - `README.md`, `README.en.md`
   - `COMPLIANCE.md`, `SECURITY.md`, `AGENTS.md`
   - `test/dev-env/scenario.md`, `test/impl/*/scenario.md` (시험 영향 판단용)

2. **요구사항 파악** — 사용자 입력에서 새 요구사항을 명확히 정리:
   - 모호하면 **한 번에 묶어 질문**: 기능 명칭, 우선순위(P0/P1), 성공 기준, 유형(F/NF/SCOPE 등).
   - 추측 금지 — 모르는 값은 `가정:` 표시.

3. **문서 업데이트** — §1.2 매트릭스 기준 영향 파일만 편집. §3 각 파일 규칙 적용.

4. **PRD 변경 이력 갱신** — PRD.md 맨 끝 `## 변경 이력` 에 한 줄 추가 (§4).

5. **시험 영향 안내** — 변경이 기존 시험 시나리오를 깨면 해당 `test/impl/<Nth>/scenario.md` 에
   `> ⚠️ 요구사항 변경으로 재시험 필요` 주석을 추가하고 사용자에게 보고.

6. **보고** — 수정된 파일 목록 + 각 파일의 변경 요약 + 소스코드 미수정 확인 메시지.

7. **안내** — 문서 갱신 완료 후:
   > 문서가 현행화됐습니다. 구현을 이어가려면 `wds-implement` 로 다음 이터레이션을 진행하세요.

## 3. 파일별 업데이트 규칙

### 3.1 PRD.md

- **기능(F) 추가**: `## 3. 범위` 의 "이번 릴리즈 핵심 기능" 목록에 항목 추가. 우선순위(P0/P1) 명시.
  동시에 `## 4. 사용자 경험` 에 해당 시나리오 스텁 추가(없으면 생략).
- **비기능(NF) 추가**: `## 5. 성공 지표` 또는 `## 7. 기술메모(풀스펙)`의 비기능 요구사항에 추가.
- **SCOPE 변경**: `## 3. 범위` In/Out 목록을 이동(Out → In 또는 그 반대). 이유를 한 줄 주석으로.
- **기존 내용 삭제 금지** — 이동(Out에서 In으로)은 OK, 삭제는 사용자 명시 요청만.
- **모르는 값**: `가정:` 태그 사용.

### 3.2 README.md (한글)

- **기능 추가**: `## 구현된 API` 또는 `## 주요 기능` 섹션에 신규 항목 추가.
  해당 섹션이 없으면 `## 다음 단계` 바로 위에 `## 예정 기능` 로 추가.
- **NF 변경**: `## 환경 설정` 또는 `## 트러블슈팅` 에 관련 설정/주의사항 추가.
- **기존 사용자 섹션 보존** — 표준 섹션만 갱신, 사용자 커스텀 섹션 삭제·이동 금지.
- **멱등**: 이미 동일 항목이 있으면 덮어쓰지 않고 기존 항목 아래에 버전/날짜 주석으로 갱신.

### 3.3 README.en.md (영문)

- README.md 와 동일 구성으로 영문 번역 적용.
- 기술 용어는 영문 원어 그대로(예: "인증 추가" → "Add JWT authentication").
- README.md 업데이트 시 **항상 함께** 업데이트 (누락 금지).

### 3.4 COMPLIANCE.md (업종 오버레이가 있는 경우만)

- **COMPLIANCE 유형** 변경: 해당 규제·데이터등급·시험 섹션 갱신.
- 새 규제 요구(예: "CSAP 인증 필요" 추가): `## 한국 규제` 표에 항목 추가 + `## 추가 시험` 에 케이스 추가.
- 데이터 등급 상향(예: "결제 정보 추가" → PCI-DSS 적용): `## 데이터 등급` 행 추가 + 비프로덕션 반입 금지 명시.

### 3.5 AGENTS.md

- 새 기능이 AI 에이전트 행동 규칙에 영향을 주면(새 금지 패턴, 새 표준 경로 등) 관련 섹션 갱신.
- 대부분의 기능 추가에는 영향 없음 — 명확한 영향이 있을 때만 수정.

### 3.6 SECURITY.md (bio-rag-research 또는 COMPLIANCE 유형 시)

- 보안 강화 요구(인증·암호화·감사로그 등): 관련 항목 추가.

## 4. PRD 변경 이력 형식

PRD.md 에 `## 변경 이력` 섹션이 없으면 맨 끝에 생성. 있으면 최신 항목을 맨 위에 추가.

```md
## 변경 이력 / Changelog

| 날짜 | 유형 | 내용 | 영향 파일 |
|---|---|---|---|
| YYYY-MM-DD | F/NF/SCOPE/DESIGN/COMPLIANCE | 변경 요약 한 줄 | README.md, ... |
```

날짜는 `currentDate` 컨텍스트 사용. 없으면 `가정: 오늘 날짜`.

## 5. 절대 금지 규칙

- **소스코드 수정 금지** — `.ts`, `.tsx`, `.js`, `.py`, `.go`, `.rs`, `.kt`, `.swift`, `.dart`,
  `.cs`, `.java` 등 모든 소스 확장자 파일은 이 스킬 범위 밖. 소스는 implement 에서만.
- **기존 PRD 항목 무단 삭제 금지** — 이동은 가능, 삭제는 사용자 명시 확인 후.
- **추측으로 요구사항 생성 금지** — 사용자 입력에 없는 내용을 임의 추가하지 않는다.
- **파괴적 변경 금지** — 기존 문서 구조(섹션 순서·링크)를 깨는 수정 금지.

## 6. implement 연동 패턴

`wds-implement` 실행 중 사용자가 새 요구사항을 언급하면:

1. **즉시 중단** — 현재 구현 단계를 완료한 뒤(또는 자연스러운 중단점에서) 정지.
2. **wds-living-doc 스킬 활성화** — §0 trigger 조건 충족으로 인라인 처리.
3. **문서 갱신** (§2 절차) 완료 후 구현 재개.
4. 새 요구사항이 현재 구현 이터레이션 범위를 벗어나면:
   - PRD 에만 기록 + "다음 이터레이션에서 구현" 안내.
   - 현재 `test/impl/<Nth>/` 범위를 넓히지 않는다.
